# Company agent 交付可靠度優化設計

本次優化針對上一批104件實測的具體失敗，提升完整交付及錯誤恢復的可靠度，再比較data使用Flash或Argon。新版為graph 28；正式服務的部署與模型設定保持原狀，驗證使用隔離dev與合成來源。

## 任務編排與角色責任

沿用hybrid編排與specialist Office分工，模型在工作建立時固定。一般說明可由主協調直接回答；有界Excel任務由data連續讀取、計算、修改及產檔，避免無必要交接。Word與PowerPoint由document製作；跨檔依賴等待真正統計憑據，最後由reviewer獨立讀取有效最新版。

| 角色 | 責任 | 比較模型 |
| --- | --- | --- |
| coordinator | 需求整合、完整交付計畫、委派、版本取捨及最終驗收 | gemini-3.5-flash-lite |
| data | XLSX讀取、工具統計、單位換算、加權、原簿修改及公式圖表 | gemini-3.8-flash 或 gemini-4-argon |
| document | Word／PPT／文字製作及精確文字修訂，依同一統計憑據產出 | gemini-3.5-flash-lite |
| reviewer | 唯讀檢查來源、有效產物與數字，不自行重製或批准外部寫入 | gemini-3.5-flash-lite |
| knowledge、research、engineering、eip | 依需求處理各自來源；本次Office比較不主動使用外部服務 | gemini-3.5-flash-lite |

Office產製只有一個負責子任務；穩定work_key與outputs防止重複派工。複雜任務按依賴拆分，獨立來源探索可以並行；不能在統計尚未完成前讓文件角色猜數字。

## 完整交付計畫

原解析器不識別「另交／另製」，導致主協調只登記Excel，也沒有在鎖定時發現漏掉Word／PPT。新版擴充明確產檔語法，略過引用標籤內的「來源／讀取」等詞，保留來源及否定指令的界線。這是有界的明確檔名解析，不宣稱理解所有自然語句；歧義需求仍由模型及reviewer確認。

plan_delivery只由coordinator使用，data與document移除全域規劃工具。主協調須先登記完整且通過明確需求檢查的計畫，再委派有outputs的產檔任務；唯讀來源探索可先執行。缺計畫或委派檔名不在計畫內時，回傳結構化錯誤，不啟動子角色。外部注入計畫亦先與原始要求比對。

未通過的計畫不會寫入，因此可以依錯誤補齊後再鎖定。已鎖定計畫不可改寫，使用者規格變更仍需另開工作；不以刪除完整性檢查解決漏交。最終完成時再核對明確需求與計畫、有效檔案、數值及獨立審核。

## 版本與交付狀態

每個產物版本有獨立ID、SHA256及不可變的位元組。相同交付檔名的精確文字修訂，會以同一交易完成新版本建立、舊版superseded關係及工具回條保存。舊版留作稽核，有效清單只保留新版；新版的驗收與reviewer讀取均重新計算。

修訂必須先inspect_artifact實際讀到該ID、SHA及精確文字run，不能猜原文、跨工作修訂、覆寫來源，或從已取代版本分支。交易中途失敗則全部回滾；兩個並行修訂只有一個能取代同一有效草稿，不留下孤立新版。同一工具呼叫的已完成回放回傳既有版本，不再產檔。

不同檔名仍代表兩份交付，必須符合原計畫與本次outputs；不能藉修訂擴張產製範圍。已最終交付的工作不再接受新增修訂。子角色回條分開列有效產物與歷史，減少協調者誤把舊稿當作待交付成果。

graph版本升為28，既有27版checkpoint不會直接以新版規則續跑，舊成果仍可依原擁有權匯出。部署時須讓待續工作以原版完成，或以明確來源另開新版工作；本次沒有自動遷移待辦或執行部署。

## 錯誤恢復與可靠結案

| 情況 | 新版行為 |
| --- | --- |
| XLSX來源超過10000列 | 保留資源上限；回傳spreadsheet_resource_limit、實際列數、上限及分割來源的下一步，不截斷、不捏造、不產檔 |
| 工作表不存在 | 回覆實際執行的requested_sheet、模型要求值、可用精確名稱及一次修正方向 |
| 同一操作及來源連續兩次表名錯誤 | 停止該操作的解析I/O，回傳sheet_recovery_exhausted，交回blocked而不猜字形 |
| 未讀草稿run、修訂檔名衝突或舊版已失效 | 回傳已分類的可恢復錯誤；擁有權、雜湊及封裝損壞仍維持硬性拒絕 |
| 其他執行或最終驗收例外 | 儲存error狀態、保留草稿及checkpoint，不留在running；對使用者只呈現安全摘要，呼叫端仍收到原生例外 |
| 上游429或逾時 | 本批維持不自動重送、不fallback；保留為服務可用性失敗，與工具及數字問題分開分析 |

Word／PPT統計文字改為完整數值token比對，避免356.1被誤認成356；支援等值小數、科學記號與正確千分位。Excel維持儲存格型別、來源憑據及精確值檢查。文件提示另外要求簡報各頁具有不同目的，避免僅更換標題序號；此語意要求仍需獨立審核與產物抽查。

## 回歸與重新比較

先執行真實PostgreSQL的故障注入回歸，包含完整清單、子角色邊界、修訂回放、並行衝突、提交回滾、新版審核、列數限制及安全錯誤狀態。再執行既有公司助理測試，確認讀取、權限、核准、預算與恢復行為。

付費比較沿用前批26題、兩輪、兩模型，共104件。兩組只有data模型不同，其他角色固定Lite；medium、4096 tokens、每次300秒、每件600秒、40次呼叫。兩個角色測試分區使用各自臨時schema，共享每模型同時一件工作的鎖；完整流程逐件執行。

評估器v1.3增加來源fixture讀取：從已完成前批報告及來源SHA取回52組真正檔案與評估端獨立答案，核對案例定義及來源雜湊。只複製來源到模型可讀目錄，不提供隱藏答案、舊回答或checkpoint。主案例與獨立判分函式不修改。失敗工作的部分成果匯出也依有效版本清單取檔，避免同名歷史版本以UUID順序覆蓋新版；全部歷史另存供稽核，工作失敗不改算成功。新版結果獨立保存，不把新成功覆寫成舊失敗的補分。

替換門檻仍為正向資料工作至少33/34、比Argon少不超過5個百分點、限制對照10/10、完整流程8/8、重要錯數字與邊界違規為零；品質通過後才判斷每成功件費用或中位時間是否改善20%。少量合成模板上的結果不足以證明任意業務任務等效。

批次結束後再進行真正LibreOffice公式擾動重算、Word／PPT完整數值加驗與預覽抽查，避免影響測量耗時。真人盲評欄位保持空白，AI抽查另列。gateway記帳與未知預留分開保存；測試後撤銷臨時一般金鑰、恢復原預算綁定，保留消費並移除本批schema。

## 比較基準

本批Office測試條件另提供[Flash候選設定](../company_agent/configs/archive/config.office-v28-flash.example.json)與[Argon對照設定](../company_agent/configs/archive/config.office-v28-argon.example.json)，兩份只有data模型不同，皆為300秒請求、600秒工作、40次呼叫及4096 tokens。這些是另存的可審閱範例，不會自動套用；state_dir、來源綁定與部署仍需依實際服務配置。本批沒有測試大量並行負載，也沒有啟用NAS／EIP／公開查詢或圖片能力。

模型替換需以本版來源、工具與獨立判分重跑完整比較；執行方式見[模型替換評測](../company_agent/evals/README.md#data-角色的模型替換評測)。不同版本結果不混算，也不預設新版通過。
