# Company Agent v20 相容重構與測試紀錄

日期：2026-09-09。此次僅重構 company_agent 的協作核心與設定組織方式。

## 交付

- 八個角色各自管理 `SPEC` 與 `prompt.md`；去除多處追加提示詞／工具集合的寫法。
- 圖組裝、checkpoint State、模型節點、提示詞組裝、工作生命週期、存檔確認及結果投影分離。
- 批次規則集中；移除無用的重複初始化。角色註冊與工具集合改成不可變資料。
- 原 `company_agent.agent` 公開入口保留，仍用官方 StateGraph、ToolNode、Runtime、interrupt 與 PostgreSQL saver。
- 提示詞資源及測試基準納入 wheel，沒有新增依賴套件。
- 仍為同一圖內的循序多角色協作，沒有變更成並行 subgraph，也沒有遷移正式 checkpoint。

原 `agent.py` 為 630 行，現為 26 行相容匯出；圖組裝為 107 行。
這不是總行數減少的宣稱：拆檔與格式化增加行數，減少的是單一檔案的責任與巢狀程度。
業務解析器及共用工具保持原位，不為每個 Agent 複製實作。

完整回歸範圍包括：使用者／工作隔離、同角色不同委派上下文、計費身分、步數與恢復、
來源版本與撤銷權限、拒絕存檔、重複操作、結構化完成、檔案審核、EIP 工具批次、
讀取參數修復、Word／Excel、真實 CAD／Office 隔離容器以及本機 OCR。

跨版本測試使用重構前的真實 `agent.py`，先建立並暫停 Word 存檔工作，
再由另一版本建立新的 DocumentAgent／模型測試替身接續。確認檔案與來源不重建、
模型步數不歸零、核准才落盤、拒絕不落盤、不同使用者無法恢復。

## 環境與邊界

- Python 3.11，既有 `webui_env`；PostgreSQL 每案例建立獨立 UUID schema 並清理。
- CAD／Office 使用既有 `ai-gateway/company-cad:1`、`ai-gateway/company-office:1`，不重新安裝映像。
- OCR 使用本機服務；Office／CAD 工作者維持無網路隔離。

  也未額外呼叫付費雲端模型。上述結果不是宣稱正式遠端服務所有情境均已重新驗收。
