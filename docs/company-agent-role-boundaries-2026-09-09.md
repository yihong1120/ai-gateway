# Company Agent 角色提示詞與邊界修正

日期：2026-09-09。

## 發現的原因

原 agents/common.md 第一行將所有角色描述為「文件與知識 Agent」，且包含文件、Excel、CAD、
EIP 與研究操作方法。runtime/prompts.py 又把全體能力目錄與所有能力開關加入各角色，
甚至讓 EIP 收到「委派 eip」等協調者指令。這些內容可能干擾角色任務理解。
工具白名單及委派上下文隔離原本就存在，不能因此認定任務語意一定正確。

## 完成的修改

- [common.md](../company_agent/agents/common.md)：改成無角色身分、無專責工具步驟的共通規則；包含任務範圍、不可信資料、來源佐證、草稿標示、核准及結果說明。
- 八個角色的 prompt.md：各自定義職責、操作方法、不得接手的工作及交回方式。文件修改、Excel、CAD、EIP 的操作細節留在對應角色；沒有移除原有業務限制。
- [runtime/prompts.py](../company_agent/runtime/prompts.py)：每次只有一個角色身分；全體能力目錄僅給主協調。子角色只收到自己工具所對應的功能開關，不再收到無關的產製或委派指令。
- 工具名稱直接來自既有 ROLE_TOOLS，不另建第二份權限表；提示中的白名單仍受啟用狀態、本人權限及任務限制。
- EIP 批次提示不再套用一般私人草稿批次規則；完成協定由執行模式集中決定，不再替換角色提示詞中的句子。
- 研究／EIP 角色不再接收無須使用的本機／NAS 根目錄清單；必要來源仍可由主協調明確放入委派 context。
- 僅查詢、摘要或分析的任務不得自行產檔；需要其他專長時交回主協調，不能自行委派。審核角色回報實際讀取的 artifact_ids，不套用一般只讀子任務的空檔案清單範例。

沒有改動 Graph／State／GRAPH_VERSION、節點、checkpoint、計費、授權、工具範圍或重試機制。
角色仍在同一官方 LangGraph 內循序交接，不是改成平行或獨立子圖。

## 測試

新增 [test_role_boundaries.py](../company_agent/tests/test_role_boundaries.py)，涵蓋：

1. 共通規則沒有角色身分或專責工具指令。
2. 8 個角色 × 兩種精簡模式 × 兩種完成模式 × 兩種批次模式，共 64 種組合：唯一角色、正確工具白名單、當次任務、能力及完成提示。
3. 所有角色的相關功能開關開啟／關閉；EIP 的獨立批次規則。
4. 8 個角色呼叫他人工具均在執行前被拒絕；不產生檔案或修改來源。
5. 7 個專責角色不能自行委派或升級為協調者。
6. 文件角色只讀真實測試檔並回傳摘要：無新成果、無多餘 reviewer 委派、原文不變。

## 上線

確認公司助理、EIP 自動及手動工作均無執行中／排隊中工作後，已重新啟動 openwebui.service。
管理員與一般使用者的工作台、成果清單、帳號連線頁、EIP 狀態、模型選單與本人計費身分檢查通過。
未登入跳轉、無效請求及 CSRF 防護保持正常；六個 UI 資源與套件內容一致。
沒有重設帳號、改寫行事曆或更新既有模型設定。

## 保留的限制

這次消除可確認的提示衝突，並驗證角色工具與上下文界線，並非新增完整的任務語意授權系統。
如果模型在自己可用的工具範圍內誤解使用者需求，仍可能做錯工作。
固定模型回覆的測試證明派送與攔截行為，不證明任意真實 LLM 永不混淆。
真正禁止跨角色工具仍由程式執行；來源、歸屬、成果校核及本人確認等檢查繼續保留。
