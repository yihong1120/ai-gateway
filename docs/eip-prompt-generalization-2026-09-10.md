# EIP 提示詞通用化與實際模型測試

## 修改範圍

依使用者要求，移除附件組、行事曆及長文件索引提示詞中的特定工程名稱、事項範例、固定日期及案例原句。改以文件結構、事件關係、時間用途、來源證據與條件是否成立定義判讀原則；受限更正提示也不指定特定文件用語。

保留 JSON 欄位、來源座標、容量限制及使用者要求的 `[AI產生]` 標記。這些是介面契約，不是業務案例關鍵字。沒有更換模型、改變權限、移除來源驗證或去重機制；沒有批次重跑正式紀錄。

參考 OpenAI Docs 的明確指令與輸出格式、評測及多樣輸入建議；依使用者要求，不將具體業務案例置入正式提示詞。[官方提示詞指引](https://developers.openai.com/api/docs/guides/prompt-engineering)

## 實測發現與修正

首輪通用化提示詞實測 10 題，6 題通過、4 題未通過。未以隱藏失敗或放寬驗證處理：

- 明確區分 `group_status`（來源組成與主公文關係）和 `events[].status`（事件是否可排程）。事件缺少日期不等於文件關係不明。
- 修正時間驗證器：只有同一連續、順向時間區間能沿用前端時段；不能跨句、跨事件或覆寫明載時段。這是通用時間格式處理，不是案件關鍵字規則。

## 最終測試

使用原部署的 `DeepSeek-V4-Flash`，10 題全部重新呼叫模型，通過 56 個檢查。沒有重播固定答案；預期答案只供測試端比對，未傳給模型。

| 情境 | 最終結果 |
| --- | --- |
| 明確交付期限 | 正確日期及 CSV 列 |
| 更換專案、日期與表達方式 | 正確日期及 CSV 列 |
| 日期與時段只在附件 | 正確跨附件取值及連續時段 |
| 相對期限缺起算日 | 保留事件待確認，不產生行程 |
| 要求優先辦理但未定日期 | 保留事件待確認，不產生行程 |
| 僅有已完成歷史紀錄 | 不新增行程 |
| 原活動已撤銷 | 不新增行程 |
| 尚待同意的安排 | 保留待確認，不當作已核定 |
| 同文件兩件不同日期工作 | 保留兩件，不混合日期 |
| 日期使用不同欄位名稱 | 正確識別，不套用背景日期 |

來源為測試用合成公文文字，文字讀取用替身；模型呼叫、LangGraph 流程與欄位驗證皆實際執行。沒有執行正式 EIP 行程新增、附件上傳或通知。

- EIP 回歸測試：295 項通過，包含啟用的 Office 容器測試。
- 公文處理器測試：66 項通過。
- 合計 361 項回歸測試，另有上述 10 個實際模型情境。
- 首輪與最終輪合計 20 次模型請求；最終輪每題一次，沒有自動重試。
- 測試案例保存在 `tests/eip_prompt_cases.py`，不加入正式提示詞；`tests/test_eip_prompt_contract.py` 檢查這項隔離。
- 原提示詞備份、兩輪回應及驗證紀錄位於本機私有暫存目錄 `/tmp/eip-prompt-general-jMA0mr/`，不保證永久保留。

測試通過代表這批已覆蓋情境通過，不代表所有未見文件永遠不會失敗。
