# Company agent 研究完成錯誤修正

原工作已取得網路來源，但空網頁擷取被當成工具錯誤，且第九次網路呼叫被硬編碼八次上限拒絕。子任務因此固定標示 partial；協調者反覆提交 completed 後觸發停止保護。

- 移除 research adapter 的每工作八次工具限制，保留工作步數、本人計費、服務額度及持久工具回條去重。
- Tavily 成功回應但沒有可用文字時，回傳 `status=no_content`、空結果與明確限制。不是已讀全文的證據；模型可改查其他來源。
- HTTP、權限、未知回條等錯誤仍停止相應操作，不自動重送。
- 加強研究與協調提示：保留使用者指定災害名稱，區分實際施工工期、行政期限與整體重建期程，保留來源網址。

## 驗證

- PostgreSQL + 真實 LangGraph、模擬遠端服務：research、enterprise completion、safe batches 共 42 項通過。
- 角色邊界與架構測試 17 項通過。
- 新增超過八次搜尋與空擷取後正常完成的整合測試；驗證失敗頁面不會產生 page_extract 來源，以及 HTTP 429 仍回報錯誤且不重送。
- 使用原工作同一已驗證帳號、部署模型與 Tavily，原問題在獨立 schema 實測，沒有修改原工作或聊天。實測會消耗本人模型與 Tavily 額度；測試 schema 完成後移除。
- 部署健康與管理員／一般使用者 smoke check 通過（入口、工作清單、連線、計費身分及無效請求防護）。

實際模型查詢前兩輪均為 `done`、`errors=[]`，分別 7／6 個模型步驟與 31／19 個來源。內容檢查發現事件名稱被替換，因此另補協調者保留事件原名的提示。第三輪（最終提示版本）在第 6 步遇到上游 HTTP 429，已有 26 個來源但未完成；未自動重試。不能把第三輪說成成功，也不能宣稱最終事件名稱提示已通過實際答案驗收。原八次限制及空擷取阻擋完成的問題由回歸測試與前兩轮實測確認已修正。
