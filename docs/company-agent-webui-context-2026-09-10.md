# Company Agent：Open WebUI 上下文精簡

## 本次調整

Open WebUI 是聊天歷史及分支的唯一來源。Pipe 使用已驗證使用者的已儲存聊天室，
以 Open WebUI 官方 `get_message_list` 取得目前分支，取代只拼接前次指令與前次回答的做法。
不信任請求 body 自帶的聊天紀錄，不帶入歷史的 system／tool 角色、tool_calls 或角色名稱。
追問即使另外附上新檔，也會保留目前分支的文字背景。

主協調收到分支背景；專責 Agent 只收到最新指令、本次委派及必要摘要，不取得整段聊天歷史。
歷史回答不是當前工具成功、審核通過或外部寫入的證據。既有工具合約、角色權限、
本人計費、審核、步數限制及 PostgreSQL checkpoint 均未改變。

佇列只暫存本次執行輸入；工作回傳 checkpoint 結果後移除佇列中的 conversation。
續跑使用 checkpoint，不重新拼裝聊天歷史；新追問再從 Open WebUI 的所選分支取得背景。
`runtime/history.py` 保留的是工具紀錄的角色視圖與委派判定，不是另一套聊天歷史管理器。

## 檔案沿用

- 本次附件位於 `uploads`；目前分支歷史工作的附件位於唯讀 `history_N`。
- 來源工作需同一 owner、聊天室、計費身分，並通過既有工作狀態與 NAS／EIP 綁定檢查。
- 不再將原檔與整串歷史成果複製進每個新工作，也不再累積 `previous_N` 檔案。
- PostgreSQL 成果首次沿用時，在原工作私人目錄建立一份 0600 快取；後續重用並驗證 SHA-256。
- 原始檔案、既有成果、舊 checkpoint 及歷史處理紀錄未刪除。
- 附件格式集中在入列邊界驗證；下載階段仍保留本人權限、圖片編碼、單檔及總大小限制。

其他模型處理、尚未進入公司助理的歷史附件不會自動掛載，須重新選取上傳。
分支文字超過 60000 字或分支不完整時明確提示，不靜默截斷或改用其他分支。
本次沒有新增聊天摘要模型呼叫，也沒有調整使用者額度；實際 token 用量仍取決於分支長度。
