## 驗收方法

依 [OpenAI Docs 評測原則](https://developers.openai.com/api/docs/guides/evaluation-best-practices)，
使用具體任務指標、真實資料與合成對照資料、獨立判分及人工檢查，並保留失敗紀錄。
逐筆分類取代籠統的模型自評，但分類本身仍可能錯，不能當成真值。
訊息分層參考 [Responses API](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)。

檢查日期、筆數、責任人、完整原文、AI 標記、私人設定、EIP 解析、專案匹配及既有匯入收據。
日期待確認而不匯入，是該類案例的正確結果；有明確日期卻漏掉，不能因保護機制擋住便判成功。
專案不在當下可選清單，不得猜 ID 或改分到其他專案；保留未匹配狀態，不計為專案匹配成功。
