## 修正機制

1. 同組附件使用單一版本的 JSON 契約，不再把單份文件舊格式與新事件格式、專案前綴規則疊在一起。明確規定 `events` 是頂層陣列，改名證據與行事曆欄位分離。
2. 在同一 LangGraph 任務內，對特定陣列／行號格式及工地來源引用錯誤，最多更正一次。沿用已讀取的完整來源；不重做 PDF／Word，不重送 EIP 寫入。
3. 更正後仍須通過相同證據驗證。不能減少先前事件數以求通過；超過事件數容量不重試、不截斷。缺日期、日期矛盾、附件關係不明、雲端請求失敗不進入格式更正迴圈。
4. 行事曆錯誤獨立持久化為 `calendar_errors`；不再只顯示泛稱 PDF／Word／CSV 未完成。
5. 已完整輸出、但停在已知「EIP 預覽內容不符」的舊案件，可在下次發現時接續一次既有 CSV 預覽。只允許寫入前失敗且無匯入紀錄的案件；仍重新驗證 CSV、預覽及去重收據。重複失敗不循環重開。
6. 不接受只引用「發文日期／收文日期／文件匣紀錄時間」作為事件日期；來源有「一週內」不代表可以用發文日當期限。
7. 原文明載「至翌日幾時」，但模型省略結束資料時，阻擋把它當成缺少結束時間而套用 60 分鐘。
