## 實際測試找出的修正

1. 專案歸類後的附件流程原先只接受無專案行程；已改為傳遞並驗證專案 ID 與分享對象。
2. EIP 編輯會把未設定的提醒欄位正規化為 `0/0000`，整日行程會補隱藏時間；驗證允許已確認的等價表示，仍嚴格核對日期、實際時刻、內容及自訂欄位。
3. `assigning_projects` 中斷狀態已納入重啟恢復，轉為待檢查，寫入結果不明不重送。
4. 正式寫入前先讀回並核對原行程，人工修改過內容時停止更新。

## 專案成員分享的實測限制

EIP 在指定 `proj_id` 時自動將專案成員加入分享對象，即使送出本人限定 `pub` 與 `public=0` 亦然。
因此不能將「參與專案」解釋成保證只有本人可見的純標籤。

新增按綁定帳號保存的 `calendar_project_member_sharing` 設定，預設關閉；更換 EIP 身分時重設。
使用者同意後可透過 `AutomationStore.set_calendar_project_member_sharing(owner, True)` 啟用。
啟用後每次讀取現行專案與成員名單並核對實際分享對象，不容許額外對象混入。
未同意前，公文行程與附件仍匯入私人事項，顯示未啟用專案成員分享的原因。

這次實際測試驗證 CSV 至 EIP 的匯入、專案歸類、附件與去重鏈路；未另外呼叫付費 LLM 重新分析正式公文。
公文來源驗證、模型輸出處理與排程工作流程由離線回歸測試覆蓋。
