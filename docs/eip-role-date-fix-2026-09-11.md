# EIP 事件責任與相對日期修正驗收

## 結論

本輪僅修改每小時 EIP pipeline 共用的公文／CSV 分析及補產路徑，未修改 company_agent。
程式回歸通過；兩件真實文件的最新隔離驗收為 **1 件通過、1 件未通過**，不能宣稱全面修復或正式部署成功。
沒有重啟正式服務、變更正式模型設定或新增／修改 EIP 行程及附件。

使用者接受無匹配專案：沿用原有私人事項 fallback，不猜測專案 ID。
獨立驗收現在接受 unmatched；ambiguous、invalid 及去重未確認仍不得算通過。

## 修改內容

- 判讀先抽取事件，再產生公文改名欄位；明確區分執行者、成果接收者與文件受文者。
- 增加精簡 assignment 資料：執行者、時間條件原文、日期種類、相對期限起算日。
  程式只核對可驗證欄位，不用專案名、文件 ID 或案例關鍵詞決定責任。
- 缺起算日、未指定日期，或把不含曆日的時間表達誤標為 explicit 時，保留為日期待補。
  原始候選保持不變供追查；未據此推算／匯入日期。已給曆日若與引文矛盾，仍由原日期驗證攔截。
- 時間判讀要求連同表格欄標閱讀；語意核對明確允許截止事項以期限日作為行事曆日期。
- 語意核對逐筆保留 keep、合併 merge、隔離 reject。只有有來源依據且獨立核准的項目可產生 CSV。
  退回項目保存 pending_events、清空排程日期並保留理由；不依核對建議重新生成答案自我批准。
  全組問題、所有項目退回、核對格式錯誤或服務失敗仍不匯入。
- 產生的標題未另引來源時沿用已驗證的 action 引用，仍須通過獨立語意核對；不再重複索取相同行號。
- CSV 補產也採相同已核准子集規則，保留 calendar_pending，不因其他待補事項阻擋有效行程。
  每小時流程保存未完成事項；既有 PDF／Word 與匯入去重收據不重做。
