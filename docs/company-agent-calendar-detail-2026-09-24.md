# Company Agent 行程詳細內容與附件（2026-09-24）

## 原因

Company Agent 的 `eip_calendar_query` 原本只回傳主旨、日期和起訖時間，沒有保留可開啟詳細頁的 event ID，也沒有詳細頁工具。底層 Netask 連接器已有 `calendar_detail()`，但僅供既有行程匯入校驗使用，未接到 Agent。清單缺少內文被誤解為 EIP 沒有內容。

## 修正

- 清單保留伺服器的 event ID，對模型回傳本使用者、本工作、本 EIP 綁定版本的 handle。
- 新增 `eip_calendar_detail(handle)`，透過既有唯讀 `Detail/cm/viewdtl` 取得事項內容與附件清單。同一 handle 在同一工作重複查詢使用既有工具回條，不因模型換一個 tool-call ID 重讀。
- 詳細頁附件沿用 `eip_read_attachment` 與現有附件處理流程。下載前重新核對附件仍屬於該行程；後續閱讀分頁共用下載快照。
- 修正附件介面不一致：Netask 下載及 Office 轉 PDF 使用檔案串流，Company Agent 原先仍假設為 bytes。現在按串流檢查大小、讀取與關閉，不增加另一套下載或轉檔實作。
- EIP 及主協調提示詞改為追問詳細內容時先讀詳細頁；內文足夠就回答，需要附件正文才下載。對使用者不輸出內部 handle。
- 回覆保留來源限制：行事曆的預留結束時間不等於公文原訂時間，會勘通知不等於會後結論。

僅列行程不逐筆讀詳細頁；詳細頁未回傳附件正文時不能宣稱已分析附件。不修改 EIP 行程、不寄信、不增加模型 fallback 或自動重試。
