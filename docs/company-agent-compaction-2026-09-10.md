# company_agent 聊天摘要壓縮驗收（2026-09-10）

## 設計與範圍

Open WebUI 仍保存原始聊天室與訊息分支。company_agent 只在送給協調者的暫時訊息視圖中，使用官方 [SummarizationMiddleware](https://docs.langchain.com/oss/python/langchain/middleware/built-in#summarization) 壓縮較早聊天；不另建一套原始聊天 history。

- 預設舊聊天估算達 16,000 tokens 時壓縮，保留近期約 4,000 tokens。以偏保守的中文字元估算法處理 LiteLLM 模型別名，不宣稱等於模型實際 tokenizer。
- 保留系統指令、本次使用者要求、來源清單與本次工作的全部工具訊息。摘要不覆蓋 PostgreSQL checkpoint、核准、去重或執行回執。
- 大段歷史文字分段交給摘要，不使用官方預設 4,000-token 截斷；原始文字仍留在 WebUI 與原工作 checkpoint。摘要本身仍可能遺漏語意，查核日期、工程數據與執行成果須回查原始來源。
- 摘要快取加密保存在既有 PostgreSQL，以使用者、已驗證計費身分、聊天室、訊息 ID／內容、模型、提示詞、摘要設定與帳號綁定版本組合辨識。編輯舊訊息不會誤用舊摘要；分支共同且未變更的前綴可安全重用。
- 摘要使用本人既有 LiteLLM 模型，計入本人額度、模型步數及工作 token 統計；快取命中不再呼叫模型。未新增服務帳號或免扣費模型。
- 官方版本固定為 langchain 1.2.10。僅覆寫其非公開非同步摘要生成 hook，以接入計費／快取並傳遞失敗，避免官方預設把模型錯誤字串當成成功摘要；分段後的觸發、保留及訊息 reducer 沿用官方機制。升版須重新驗證此 hook。
- 空白、截斷、未縮短或含工具呼叫的摘要不採用。失敗保留原文；同一工作不自動重複扣款。摘要完成而後續模型失敗時，恢復工作會重用成功摘要。

## 明確保留的限制

不是無限聊天：仍有單批 200 萬字資源上限、本人費用與工作步數上限；目前工作的工具軌跡仍受上下文上限保護，不在本次聊天摘要範圍。沒有宣稱模型摘要無損，也沒有建立跨程序 exactly-once 計費承諾。摘要快取目前隨公司資料保存，尚無獨立 TTL 清理政策。

## 測試

使用實際 PostgreSQL 隔離測試 schema、官方 ChatOpenAI HTTP 介面與官方 LangChain／LangGraph；LLM HTTP 使用替身，未呼叫付費模型，未新增真實 EIP 行程或修改 NAS。

- 12 項摘要測試：短聊天、完整分段、超過原 60,000 字上限、同分支快取、追問重用、編輯／分支／聊天室隔離、跨使用者隔離、帳號重新驗證、失敗不重扣、無效摘要、預算與 checkpoint 恢復，並檢查摘要 token 納入工作統計。
- 完整測試包含資料庫、CAD 容器、Office、本機 OCR 及 Open WebUI 入口。
- 打包 wheel 後另行執行架構、資源、角色邊界、UI 與錯誤邊界測試；前端另跑兩組 Node 測試。
- 依賴鎖定新增 langchain，並將原本過期的 SQLite checkpoint 鎖定整理為專案已宣告的 PostgreSQL 依賴；沒有對正式 Python 環境執行 pip／uv sync 或模型升級。
- 測試環境實際版本：langchain 1.2.10、langgraph 1.0.8、langchain-core 1.6.0、langgraph-checkpoint-postgres 3.0.5。uv.lock 解析的 graph 1.0.10 並非本次正式環境升級或驗證聲明。
